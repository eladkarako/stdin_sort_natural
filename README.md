<h3><img src="resources/app.png" /> stdin_sort_natural</h3>sorts and unique whatever it gets from `STDIN`.  data would change (by design)1. lines would be trimmed of space and tabs from start and end.2. removing all `\r` or `\v`.3. no empty lines.4. eventually lines will be joined, with `\r\n` or `\n` (depend on your OS).<hr/>code mostly do stuff in bytes,  handling things actually really gracefully,  actually no str or string functionality,  and it will try to parse same words with number segments properly, including parsing `0002` as `2` for example.  the sorting algorithm should be consistent,  but it is probably different than any other you've used,  the code handles most UTF-8 fine, but probably fallback to Unicode sorting based on the bytes order..  .. which often is sufficient, as it is, at least - consistent.  you can pipeline the example text file as a test (it includes many tabs, and spaces, and letter case variations).  use `type resources\example.txt` (Windows) or `cat resources/example.txt` (linux), followed by ` | stdin_sort_natural` (make sure you are in the place you've downloaded the file..).if you want windows cmd to view Unicode/UTF-8 characters properly you'll need a new font such as `Consolas` and running `chcp 65001 1>nul 2>nul`.  for linux running `locale` should give you something like `LANG=en_US.UTF-8`, you might need to run `sudo locale-gen en_US.UTF-8`, then `sudo update-locale LANG=en_US.UTF-8`, then `export LANG=en_US.UTF-8`. try test it using `printf 'UTF-8 test: ✓ 漢字 — €\n'` .
